标书哨兵

多 Agent 标书编写系统。把招标文件解析为结构化知识，检索相关章节， 由 Writer / Reviewer / Reviser 协作生成投标文件， 再经 21 项合规检查、跨章节一致性台账与导出前门禁 交付。

核心能力

从解析到交付的每个环节都有结构化产物；生成式 AI 的自由度受确定性证据链约束。

01

解析与知识库

MinerU 云端解析（PyMuPDF 兜底）、目录/页码对齐、表格与页脚清理； DeepSeek 结构化抽取后写入 Chroma 向量库。

02

RAG 与证据链

语义检索优先，Chroma/智谱不可用时回退关键词；工程量清单等附件执行 BOQ 专项检索，关键事实带 [E#] 引用。

03

多 Agent 写作

可编辑大纲 → 逐节检索 → 并行写作 → 审查 → 条件修订 → 确定性组装； 章节级检查点、续跑、单节编辑与版本恢复。

04

合规与门禁

21 项合规检查、跨章节事实台账、需求覆盖矩阵与引用契约； block 时严格导出被拒，审批绑定正文 content_sha256。

05

协作与治理

评审评论、@提及、指派、截止时间、多级回复与项目看板；5 角色 RBAC、 项目级 ACL、append-only 审计哈希链。

06

生产与运维

Docker Compose + Nginx TLS、健康检查、Prometheus/Grafana、备份恢复、 CI/E2E/压测与供应链扫描，支持私有化部署。

架构

FastAPI + Celery + PostgreSQL + Redis + MinIO + Chroma；前端为 React 19 与 Electron。

招标 PDF→ 解析 / 抽取→ Chroma 向量库→ 多 Agent 写作→ 合规 / 一致性 / 门禁→ DOCX / PDF / DOC

写作链路固定使用 Writer、Reviewer、Reviser 三个核心 LLM Agent， 只处理施工组织设计的叙事章节；表单、附件、组装、合规与门禁均为确定性代码或模板。 详细说明见 README 的 Agent 工作流。

快速开始

Windows 一键启动，或使用生产 Compose；模型密钥从 .env 读取，永不入库。

本地开发（Windows）

git clone https://github.com/lj105183000/much-agents.git
cd much-agents
copy .env.example .env
start.bat

生产部署

docker compose -f docker-compose.prod.yml up -d --build

# 生产只暴露 Nginx 80/443
# API/worker 非 root、只读根文件系统
